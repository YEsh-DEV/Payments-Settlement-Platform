# PayCore: Audit Findings Matrix (Hypotheses F1 – F21)

**Review Target:** PayCore End-to-End Verification Report vs Codebase & Playbook Specification

Every finding in this document was evaluated as a hypothesis against the actual codebase, test suite, and playbook.

## Findings Summary

| ID | Topic | Verdict | Evidence | Remediation Work Package |
| :--- | :--- | :--- | :--- | :--- |
| **F1** | Invariant Drift | **CONFIRMED** | `PostingEngine.java:108-212`, `agent_report.md:157-165`. Report maps I3 to currency, I4 to positive amounts, I5 to non-negative liability, I8 to monotonic sequence. Playbook Section 3.4 defines I3 as global zero-sum, I4 as cached balance = sum of entries, I5 as payout limit, I7 as refund limit, I8 as single operation link. | **WP-B** |
| **F2** | I5 Negative Balance Contradiction | **CONFIRMED** | `PostingEngine.java:189-203`. Code checks `if (available < 0) throw PayCoreException(UNPROCESSABLE_ENTITY)` for all journals. Playbook Section 3.1 & 3.4 explicitly specifies that `SELLER_PAYABLE` may go negative through refund or dispute journals, and only payout requests may never overdraw it. | **WP-B** |
| **F3** | Missing Integrity Checker (F-L-09) | **CONFIRMED** | `services/ledger-service`. No `IntegrityController` or `/v1/integrity` endpoint exists. No nightly scheduled verification job, and no `ledger_integrity_violations_total` metric exists. | **WP-B** |
| **F4** | Idempotency In-Progress & Header Gaps | **CONFIRMED** | `IdempotencyService.java:49-54`. Code uses error code `concurrent_request` instead of 409 `request_in_progress`, and `idempotency_conflict` instead of 422 `idempotency_key_reused`. Response does not emit `Idempotent-Replayed: true` header. No caller scope column in `idempotency_keys` table. No 7-day cleanup job. Stale in-flight records cannot be taken over after a crash. | **WP-C** |
| **F5** | Benchmark Provenance Lack of Raw Output | **CONFIRMED** | `perf/results/`. The `perf/results/` directory does not exist. Benchmark tables in `docs/hot-account-report.md` were synthetically compiled without raw JSON run outputs. | **WP-D** |
| **F6** | Benchmark Workload Protocol Mismatch | **CONFIRMED** | `benchmarks/k6/workload-w2.js`. Script executes 100% captures. Playbook 9.3 requires W2 to be 70% captures, 20% refunds, 10% payouts. Playbook concurrency levels (1, 8, 32, 64, 128 VUs) and 3-run median decision rule were not applied. | **WP-D** |
| **F7** | Hot-Account Chart of Accounts Discrepancy | **CONFIRMED** | `SystemAccountInitializer.java:18-41`. Initializes non-standard `USER_FUNDS_IN_TRANSIT` instead of playbook Section 3.2 system accounts (`PROVIDER_RECEIVABLE`, `BANK_CASH`). Report claims merchants are hot, whereas in the playbook system accounts (`PLATFORM_FEE_REVENUE`, `PROVIDER_RECEIVABLE`) are hot and sellers are standard pessimistic accounts. | **WP-D**, **WP-B** |
| **F8** | Dynamic Switching Contradiction | **CONFIRMED** | `agent_report.md`, `docs/runbook.md:SOP-05`. Docs describe dynamic runtime switching of strategies. Playbook Section 9.1 specifies strategy is chosen at startup via `paycore.ledger.strategy` and requires process restart. | **WP-D** |
| **F9** | Unexplained Abort Rates | **CONFIRMED** | `docs/hot-account-report.md`. Strategy S1 shows 1.8% and 6.4% abort rates without breakdown into deadlocks, timeouts, serialization failures, or 4xx responses, and without verifying safe idempotency retries. | **WP-D** |
| **F10** | Stripe Count Mismatch | **CONFIRMED** | `SystemAccountInitializer.java:35-39`. Stripe count configured as $N=10$, while playbook Section 9.2 default is $N=16$. | **WP-B**, **WP-D** |
| **F11** | Crash Test Protocol Gaps | **CONFIRMED** | `tests/crash-harness/sigkill-crash-test.sh`. Script runs invariant queries against an idle database in a loop without killing the service process, without executing concurrent W2 load, without in-flight request replays, and without outbox verification. `scripts/crash-test` does not exist. | **WP-E** |
| **F12** | Settlement to Ledger Integration Gaps | **CONFIRMED** | `BatchCutoffService.java:60`, `AdjustmentService.java:135`. Settlement service creates local payout and adjustment rows but does not make service-token authenticated REST calls to ledger `POST /v1/payouts`, `POST /v1/adjustments`, or `POST /v1/provider-deposits`. | **WP-F** |
| **F13** | Consumer Robustness & Outbox Gaps | **CONFIRMED** | `OutboxRelayService.java:39-57`. Outbox relay does not use `FOR UPDATE SKIP LOCKED` and publishes to Kafka inside the database transaction. `SettlementCandidateConsumer.java` lacks backoff retry and DLQ topic (`ledger.domain-events.dlq`). Topic name is `paycore.ledger.events` instead of `ledger.domain-events`. | **WP-F** |
| **F14** | Unqualified 100% Accuracy Claim & Fee Model | **CONFIRMED** | `ReconciliationEngine.java:172-200`, `agent_report.md`. Report claimed unqualified 100% precision and recall without per-fault breakdown or synthetic qualification. Fee model used floating-point arithmetic without configured `providerFixedFee`. | **WP-G** |
| **F15** | Subset Search Fallbacks & Duplicate Cases | **CONFIRMED** | `ReconciliationEngine.java:386`, `V1__init_settlement.sql:cases`. Solver lacks reserve-holdback tolerance fallback. Re-running reconciliation generates duplicate cases because `cases` table lacks a unique constraint or deduplication check on `(type, reference)`. | **WP-G** |
| **F16** | Missing Quality Gates & Frontend Testing | **CONFIRMED** | `pom.xml`, `web/ops-console/package.json`. JaCoCo coverage execution is unconfigured. SpotBugs and Enforcer plugins are missing. Zero ArchUnit tests written. Frontend lacks Vitest, React Testing Library, and Playwright smoke tests. | **WP-H** |
| **F17** | Lack of Scripted End-to-End Business Flow | **CONFIRMED** | Codebase audit. No `scripts/e2e-flow.sh` exists. Previous testing only verified Actuator health endpoints rather than an end-to-end flow of capture $\to$ batch $\to$ payout $\to$ recon $\to$ case $\to$ adjustment. | **WP-I** |
| **F18** | Playbook Acceptance Checklist Incomplete | **CONFIRMED** | `scripts/`. Directory `scripts/` does not exist. `scripts/seed` missing. `docs/architecture.md` missing. | **WP-I** |
| **F19** | Security Checklist Gaps | **CONFIRMED** | `services/ledger-service`. Redis token bucket rate limiter filter missing on write endpoints. Nginx lacks 20 MB client upload body cap. Deny-list fail-open behavior lacks formal ADR. | **WP-J** |
| **F20** | Misleading Wording in Documentation | **CONFIRMED** | `README.md`, `agent_report.md`. Uses terms "Multi-Tenant Databases" (actually database-per-service), "Redis Cluster / Kafka Cluster" (actually single-node in compose), marketing adjectives ("audit-grade"), host-specific `file:///mnt/nexus/...` links, and incorrect citation of RFC 6819. | **WP-K** |
| **F21** | Gateway Paths & Ports Discrepancy | **CONFIRMED** | `web/ops-console/src/api/paycoreApi.ts`, `deploy/nginx.conf`. Ops console calls `/cases`, `/batches/run`, `/auth/login` directly against `/api`, whereas nginx routes `/api/identity/*`, `/api/ledger/*`, `/api/settlement/*`. Ports and path contracts must be unified. | **WP-J** |
